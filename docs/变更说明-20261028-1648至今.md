## 十、JDK 8 兼容（本次收尾）

后端 `pom.xml` 一直是 `java.version=1.8`，但源码里混用了 JDK 9+ 的 API：在 JDK 11/17 上能编译，在 JDK 8 上直接编译失败。已全部改为 JDK 8 写法。

### 10.1 替换清单

| 原写法（JDK 9+） | 现写法（JDK 8） | 处数 |
|---|---|---|
| `List.of(...)` / `List.of()` | `Arrays.asList(...)` / `Collections.emptyList()` | 34 |
| `Set.of(...)` / `Set.of()` | `new LinkedHashSet<>(Arrays.asList(...))` / `Collections.emptySet()` | 11 |
| `String.isBlank()` | `CpsStrings.isBlank(x)`（新增工具类，语义对齐 JDK 11） | 23 |
| `stream().toList()` | `stream().collect(Collectors.toList())` | 2 |
| `Optional.orElseThrow()`（无参） | `orElseThrow(IllegalStateException::new)` | 1 |
| `List.<T>of()` | `Collections.<T>emptyList()` | 2 |
| `java.util.HexFormat`（JDK 17） | `CpsVisionCheckService.toHex(byte[])` | 1 |

同时把散落在 4 个 Service 里的私有 `isBlank` 实现统一收敛到 `CpsStrings.isBlank`。

### 10.2 新增文件

- `backend/src/main/java/com/catlbattery/common/util/CpsStrings.java`：`isBlank(String)`（null 安全，按 `Character.isWhitespace` 判定）与 `isNotBlank(String)`。

### 10.3 为什么用 `CpsStrings.isBlank` 而不是 `trim().isEmpty()`

`String#trim()` 只去掉 `<= ' '` 的字符，全角空格（U+3000）等空白会漏判；`String#isBlank()` 用的是 `Character.isWhitespace`。两者语义不同，所以补了工具类而不是简单替换成 `trim().isEmpty()`。

### 10.4 行为差异（已知且无需处理）

`List.of` 不可变、拒绝 null；`Arrays.asList` 可变、允许 null。现有代码没有依赖不可变性，也没有依赖「传 null 立即抛 NPE」，全套测试通过。

### 10.5 验证方式

```bash
cd cps/backend
mvn -o -DskipTests clean test-compile -Dmaven.compiler.release=8   # 按 JDK 8 的 API 白名单编译主代码 + 测试
mvn -o test -Dmaven.compiler.release=8                             # 392 用例 / 389 通过（3 个既有失败）
```

`-Dmaven.compiler.release=8` 会让编译器以 JDK 8 的 `ct.sym` 为准，以后谁再混入 9+ API 会直接编译报错。在 JDK 8 上直接 `mvn test` 即可，不需要该参数。

## 十一、本轮追加：照片引用统一为公开绝对 URL + 后端包结构迁移（21:00 后）

两条需求：「所有写入数据库、接口、Java↔Python 契约的都是 public 可直接访问的完整图片地址」「后端包名必须是 `com.catlbattery.*`，且**数据库字段名绝对不能改**」。

### 11.1 照片/附件只有一种形态：MinIO 公开绝对 URL

| 层 | 之前 | 现在 |
|---|---|---|
| 数据库列 | `photo_object_key`（存裸对象键，读时拼 URL） | **列名不变**（历史约定），但值统一是 `http://host/bucket/...` 完整 URL |
| Java 实体字段 | `photoObjectKey` | `photoUrl`（字段名改了，列名没改；`CpsInspectionRecordItemMapper.xml` 用 `<resultMap id="ItemMap">` 显式映射 `photo_object_key → photoUrl`） |
| Python C-01 `AttachmentRef` | `object_key` / `content_base64` 三选一 | 只剩 `url`（`extra="forbid"`，传旧字段直接 422） |
| Python C-04 判定入参 | `photo_object_keys` + `photo_urls` 二选一 | 只剩 `photo_urls`（完整 URL），响应里也只有 `photo_urls` |
| Java↔Python 附件引用 | `url` 或 `content_base64` 回退 | 只有 `url`；没有 URL 的行直接不发（Python 按「不判定」处理） |

### 11.2 需要执行的 SQL（1 条，可选但建议）

```sql
-- 本窗口唯一新增迁移：把存量「裸对象键」补成完整 URL（幂等：只改不以 http 开头的值）
-- 文件：V20261031__prefix_legacy_photo_url_object_keys.sql
UPDATE cps_inspection_record_item
   SET photo_object_key = CONCAT('http://127.0.0.1:9000/cps-attachments/', photo_object_key)
 WHERE photo_object_key IS NOT NULL AND photo_object_key <> ''
   AND photo_object_key NOT LIKE 'http://%' AND photo_object_key NOT LIKE 'https://%';
-- cps_room_check_record_item / cps_vision_check_record 同语句（见迁移文件本体）
```

执行后校验：

```sql
SELECT 'record_item' AS t, COUNT(*) FROM cps_inspection_record_item WHERE photo_object_key NOT LIKE 'http%' AND photo_object_key IS NOT NULL AND photo_object_key <> ''
UNION ALL SELECT 'room_item', COUNT(*) FROM cps_room_check_record_item WHERE photo_object_key NOT LIKE 'http%' AND photo_object_key IS NOT NULL AND photo_object_key <> ''
UNION ALL SELECT 'room_item_url', COUNT(*) FROM cps_room_check_record_item WHERE photo_url NOT LIKE 'http%' AND photo_url IS NOT NULL AND photo_url <> '';
-- 期望全为 0
```

> 说明：期间曾把列重命名为 `photo_url`，按「字段名绝不能改」的要求已回退，库里仍是 `photo_object_key`（`cps_room_check_record_item` 另有 `photo_url` 列，是历史遗留的另一列，未动）。
