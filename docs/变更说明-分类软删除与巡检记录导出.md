# 变更说明：问题分类软删除 + 非 CPS 巡检记录导出 Excel

- 提交：`ce8e2c0`（删除与导出首版）、`42b62c1`（删除改为软删除）
- 影响范围：`cps` 仓库（后端 Spring Boot + admin 前端），Android 端**无需发版**
- 数据库：需要执行 1 条迁移（`V20261030`）；若目标环境还没跑过附件列加宽，一并执行 `V20261029`

---

## 一、这次实现了什么

### 1. 问题分类可以在停用后删除（软删除）

- 两道护栏：**必须先停用**、**不能还有未删除的下级分类**
- 删除只打标记（`deleted = 1`，同时把 `enabled` 置 0），**不再因为"被历史数据引用"而拦住**
- 删除后该分类从管理端列表 / 分页 / 导出 / Android 与 web 的下拉选项里全部消失
- 历史问题、知识案例、AI 匹配记录仍按分类 ID 关联，**分类名照常显示**
- 同父级下用同名新建分类时，复用被软删除的那一行（同一个 ID，`deleted` 归 0），历史关联自动恢复；如果同名分类还活着，则提示「该父级下已存在同名分类」

### 2. 非 CPS 巡检记录导出 Excel

- 入口：管理端「巡检记录」页右上角「导出 Excel」按钮，按当前筛选条件导出
- 接口：`GET /api/cps/admin/inspection-records/export`，筛选参数与列表页一致（`typeCode` / `areaId` / `recordStatus` / `checkEmpNo` / `keyword`），上限 1 万行
- 18 列：记录ID、巡检类型、区域、巡检人、状态、提交时间、得分、AI初审结论、AI初审意见、复核人、复核时间、复核意见、整改人、整改提交时间、整改原因、短期措施、长期措施、整改照片
- 状态与 AI 结论中文化（待执行/待复核/待整改/已结束，通过/部分通过/有问题）
- 整改照片统一输出为可点开的绝对 URL（历史数据存的是裸对象键，导出时补全存储前缀）
- 顺带统一：巡检记录页 `JUDGED` 原先显示「已判定」，现在与导出一致显示「已结束」

### 3.1 推荐方式：由 Flyway 自动执行

后端启动即自动执行 `V20261030__category_soft_delete.sql`（本机已执行，当前 schema 版本 `20261030`，共 39 个迁移）。**不需要手工跑任何 SQL**，只要确认启动日志出现：

```

```

### 3.2 手工执行版（Flyway 被禁用，或要提前在目标库准备）

```sql
-- 20261030：问题分类软删除
ALTER TABLE cps_problem_category
  ADD COLUMN deleted TINYINT NOT NULL DEFAULT 0 COMMENT '是否已删除：1已删除（软删除），0正常' AFTER enabled,
  ADD INDEX idx_cps_category_deleted (deleted, parent_id, sort_no);
```

如果目标环境还没执行过 `V20261029`（附件 URL 加宽，导出与详情回显依赖它写入完整 URL），一并执行：

### 3.3 执行后校验

```sql
-- 列与索引是否就位（期望各返回 1 行）
SELECT COLUMN_NAME, COLUMN_TYPE, COLUMN_DEFAULT, COLUMN_COMMENT
  FROM information_schema.COLUMNS
 WHERE TABLE_SCHEMA = DATABASE() AND TABLE_NAME = 'cps_problem_category' AND COLUMN_NAME = 'deleted';

SELECT INDEX_NAME, SEQ_IN_INDEX, COLUMN_NAME
  FROM information_schema.STATISTICS
 WHERE TABLE_SCHEMA = DATABASE() AND TABLE_NAME = 'cps_problem_category'
   AND INDEX_NAME = 'idx_cps_category_deleted';

-- 存量数据全部是"未删除"
SELECT COUNT(*) AS total, SUM(deleted) AS deleted_rows FROM cps_problem_category;
```

`deleted_rows` 应为 0（本次不涉及任何数据回填，只加列）。

### 3.4 回滚 SQL（需要撤回时）

```sql
ALTER TABLE cps_problem_category DROP INDEX idx_cps_category_deleted;
ALTER TABLE cps_problem_category DROP COLUMN deleted;
```

注意：回滚会让已软删除的分类重新出现（且仍处于停用状态），历史关联不受影响。

## 四、部署与验证步骤

1. 执行 SQL（或直接启动后端让 Flyway 跑）→ `mvn -o test` 应通过
2. 重启后端（本机：`mvn -o -DskipTests spring-boot:run`，端口 8080）
3. 构建 admin：`cd admin && npm run build && npm run lint`
4. 功能自测

**分类软删除**

```bash
API=http://127.0.0.1:8080/api/cps/admin/master
# 停用
curl -X PATCH "$API/categories/910002/enabled" -H 'Content-Type: application/json' -d '{"enabled":false,"empNo":"你的工号"}'
# 删除（即使被历史问题引用也应返回 200）
curl -X DELETE "$API/categories/910002?empNo=你的工号"
# 选项与列表应已排除该分类
curl "$API/../master/categories?parentId=910001"
# 同名重建应复用原 ID（返回 id = 910002）
curl -X POST "$API/categories" -H 'Content-Type: application/json' \
  -d '{"parentId":910001,"categoryName":"防护用品未佩戴","categoryLevel":2,"enabled":true,"empNo":"你的工号"}'
```

预期：启用中删除返回 `400 请先停用该分类再删除`；有下级返回 `400 该分类下还有 N 个下级分类`。

**巡检记录导出**

```bash
curl -D - -o /tmp/records.xlsx \
  "http://127.0.0.1:8080/api/cps/admin/inspection-records/export?recordStatus=PENDING_REVIEW&typeCode=ROOM_CHECK"
```

预期：`Content-Type: application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`，文件内首行是 18 列表头，状态与 AI 结论为中文，整改照片为 `http://...` 绝对地址。

## 六、注意事项

- 软删除行会长期保留在 `cps_problem_category`（这是历史关联能保住的原因）。真要物理清理，需先给历史表补分类名快照，否则老记录的分类名会丢

- Android 端零改动：下拉选项来自 `/api/cps/master/categories`，服务端已过滤；历史分类名由列表接口 JOIN 得出
